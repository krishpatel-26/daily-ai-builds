# Problem framing

## User
A forward-deployed engineer, implementation lead, solutions engineer, or GTM owner coordinating a customer launch.

## Job to be done
Before committing to a launch date, understand which prerequisites are complete, which blockers remain, who owns each action, and what evidence supports the current status.

## Failure modes
- A status color hides unresolved dependencies.
- Ownership is implicit and actions stall.
- Security and access reviews appear late.
- Product adoption is mistaken for technical integration success.
- GTM communicates a date before customer acceptance criteria are met.

## Design principles
1. Evidence over optimism.
2. Named owner over vague responsibility.
3. Critical dependencies surfaced before cosmetic completeness.
4. A score that can be explained.
5. Human approval before external commitments.
