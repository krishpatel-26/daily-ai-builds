# Contract change rollout checklist

- [ ] Baseline contract matches the version the customer actually uses.
- [ ] Candidate contract version and release notes are confirmed.
- [ ] All breaking-change findings have an owner and disposition.
- [ ] Baseline request fixtures have been replayed against the candidate schema.
- [ ] New required fields have defaults, backfills or a documented migration.
- [ ] Removed fields, operations and status codes have a deprecation plan.
- [ ] Enum changes are checked against persisted and customer-generated values.
- [ ] Authentication, authorization, rate limits and semantics are reviewed separately.
- [ ] Regression tests execute in a representative non-production environment.
- [ ] Observability, rollout stages and rollback triggers are agreed.
- [ ] Customer communication and migration instructions are prepared.
- [ ] Accountable owner records the final go/no-go decision.

A report generated by the Sentinel is one input to this checklist, not proof that an item has passed.
